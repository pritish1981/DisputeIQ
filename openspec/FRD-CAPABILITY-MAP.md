# FRD → OpenSpec Capability Map

| FRD family | OpenSpec capability |
|---|---|
| FR-CAS-* | case-intake-and-management |
| FR-CLS-* | classification-and-routing |
| FR-CTX-* | authoritative-context |
| FR-EVD-* | evidence-management |
| FR-POL-* | policy-rag |
| FR-RUL-* | deterministic-rules |
| FR-CNF-* | case-confidence-and-escalation |
| FR-REC-* | recommendation |
| FR-HITL-* | human-in-the-loop |
| FR-COM-* | communication-and-closure |
| FR-AUD-* | audit-governance |
| FR-AIP-* | ai-platform-model-gateway |
| FR-WFL-* | workflow-resilience |
| FR-SEC-* | security-privacy |
| FR-OBS-* | observability-evaluation |
| API / integration requirements | api-integrations |
| FR-ARC-* | architecture-flow-controls |

The FRD remains the program-level source of truth. OpenSpec capability specs are the executable contract for implementation changes.
